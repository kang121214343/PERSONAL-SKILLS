# PERSONAL-SKILLS — 작업에 다시 쓰는 도구 모음

## 스킬이란?

- **Skill(스킬)**: Codex가 특정 업무를 수행할 때 참고하는 작업 지침과 필요한 보조 파일입니다.
- **Computer Use**: 제공된 도구로 브라우저나 앱을 조작하는 기능입니다. 이 저장소에는 재사용 가능한 조작 절차를 보관합니다. 여기의 파일만으로 PC 제어 기능이 생기지는 않습니다.
- **main**: 검증을 통과한 최신 관리본입니다.
- **branch(브랜치)**: 작업본 또는 이전본을 따로 보존하는 이름입니다. Git 브랜치는 저장소 전체의 기록을 가리키지만 스킬 이름으로 구분해 관리합니다.

## 스킬 목록

아직 등록된 자체 스킬이 없습니다. 앞으로 실제 사용과 검증을 마친 항목만 이 표에 추가합니다.

| 분류 | 보관할 내용 | 현재 상태 |
|---|---|---|
| coding | 코드 조사·구현·검수에 재사용할 방법 | 미등록 |
| documents | 보고서·기획·명세 작성 방법 | 미등록 |
| materials | Excel·발표·자료 정리 방법 | 미등록 |
| computer-use | 특정 브라우저·앱 작업의 검증된 절차 | 미등록 |

스킬 파일은 `skills/<분류>/<스킬명>/SKILL.md`에 둡니다. 실제 스킬이 생기기 전에는 빈 폴더나 임시 스킬을 만들지 않습니다. 스킬명이 바뀌어도 같은 항목을 중복 등록하지 않습니다.

## 사용하는 방법

1. 위 목록에서 필요한 업무와 지원 환경을 확인합니다.
2. Codex에 해당 스킬의 이름 또는 경로를 알려 적용을 요청합니다.
3. 여러 작업에서 자동으로 발견되게 하려면 해당 Codex 환경의 지원되는 설치·등록 절차가 필요합니다. GitHub에 올리는 것만으로 자동 설치되지는 않습니다.
4. 환경에 없는 도구·권한은 먼저 확인합니다. 설치나 권한 변경을 몰래 수행하지 않습니다.

예시 요청: “PERSONAL-SKILLS의 문서 작성 스킬을 확인하고 이번 보고서에 적용해 줘.” 현재 문서 작성 스킬은 미등록이므로 기존 제공 스킬을 먼저 검토합니다.

## 추가·보강하는 순서

실제 업무에서 재사용할 가치 확인 → 기존 스킬과 중복 확인 → 최소한의 지침·보조 파일 작성 → 구조·정상/예외 동작 검증 → 비공개 자료 제거 → 작업 브랜치에 업로드 → 검토 후 main 병합 → 이전본·검증 기록 정리.

Codex가 향후 승인된 작업을 진행하면서 이 절차를 수행합니다. 대화가 끝난 뒤 자동 감시하거나 배경에서 계속 업로드하는 시스템은 아닙니다. 작업에 필요한 모델·추론 수준은 단계 시작 시 사용자와 선택합니다.

## 업로드 전 검증

| 대상 | 필수 확인 |
|---|---|
| 모든 스킬 | SKILL.md의 이름·설명·적용 범위, 참조 파일·링크, 중복, 민감정보, 배포 권리 |
| 보조 코드 | 지원 환경에서 정상·잘못된 입력·실패 처리 실행 확인 |
| 문서·자료 | 요청 충족, 원본 보호, 결과 파일의 실제 내용·서식 확인 |
| Computer Use | 지원 도구와 대상 환경 확인, 새 화면 상태를 근거로 조작, 최소 실제 흐름 시험, 잘못된 대상·중단 처리 |

검증 도구의 형식 통과만으로 동작 성공을 주장하지 않습니다. 필요한 도구나 시험 환경이 없으면 ‘미검증’으로 남기고 **main에 사용 가능한 스킬로 올리지 않습니다**. 검증 날짜·환경·명령/절차·결과·제한·대상 커밋을 기록합니다. 실제 회사 자료 대신 가상 자료를 사용합니다.

## 버전 관리

- 최신 검증본은 main에 병합합니다. 강제 푸시와 Git 이력 삭제는 하지 않습니다.
- 수정 전 버전은 `archive/<스킬명>/<UTC시각>`으로 보존합니다. 작업 브랜치는 `work/<스킬명>` 하나만 사용하고 병합 후 정리합니다.
- **스킬별로 main을 제외한 브랜치는 2개 이하**로 관리합니다. 공통 문서는 `repository-docs` 항목으로 관리합니다.
- 3개 이상 생기면 가장 오래된 브랜치를 정리합니다. 생성 UTC·이름·커밋을 변경 기록에 남겨 순서를 판단하며, 마지막 수정일을 생성일로 오인하지 않습니다.
- 삭제 전에 해당 커밋과 필요한 파일이 main 이력 또는 유지할 보존본에 남는지 확인합니다. 미병합 작업은 보존 후 정리합니다. 생성 순서·복구 근거가 불명확하면 임의 삭제하지 않고 확인합니다.
- 이 규칙은 PERSONAL-SKILLS에만 적용합니다. WMS 등 다른 저장소의 보호 브랜치를 삭제하지 않습니다.

## 공개 저장소에서 제외할 것

비밀번호·토큰·쿠키·계정 DB, 회사 재고·단가·고객 자료, 원본 Excel, 백업, 개인정보, 민감한 로그·스크린샷을 올리지 않습니다. 공개해도 되는 지침·코드·가상 예제만 관리합니다. 설치된 Superpowers/Ponytail 등 타사 스킬은 그대로 복사하지 않고 기존 제공 기능을 사용합니다. 외부 자료를 재배포할 경우 출처와 라이선스를 확인합니다.
